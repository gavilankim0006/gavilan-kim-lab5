LABORATORY ACTIVITY
Database Migration Using LavaLust
Objective
At the end of this laboratory activity, students should be able to:

    1. Use the LavaLust CLI to manage a project.
    2. Create a controller using the LavaLust CLI.
    3. Define routes for database migration operations.
    4. Create a custom CLI command.
    5. Execute database migrations.
    6. Verify the tables created by the migration system.

Part I -- Start the LavaLust Project
Open your LavaLust project in Visual Studio Code and open the terminal.
Start the development server:
php lava serve
Verify that the application is running successfully.

Part II -- Create the Migration Controller
Use the LavaLust CLI to generate a controller:
php lava make:controller MigrationController
Open the generated controller and replace its contents with the following:
<?php

defined('PREVENT_DIRECT_ACCESS') OR exit('No direct script access
allowed');

class MigrationController extends Controller
{

   public function __construct()
   {

       parent::__construct();
       $this->call->library('migration');
   }

   public function create_migration($migration_class)
   {

       $this->migration->create_migration($migration_class);
   }
   public function migrate()
   {

       $this->migration->migrate();
   }

   public function rollback()
   {

       $this->migration->rollback();
   }

   public function rollback_all()
   {

       $this->migration->rollback_all();
   }

   public function refresh()
   {

       $this->migration->refresh();
   }

   public function status()
   {

       $this->migration->status();
   }
}
The controller provides access to the migration library through HTTP routes.

Part III -- Configure the Routes

Open:

app/config/routes.php

Add the following routes:

// Migration Routes

$router->get('create-migration/{migration_class}',
'MigrationController::create_migration');

$router->get('migrate', 'MigrationController::migrate');

$router->get('rollback', 'MigrationController::rollback');

$router->get('rollback-all', 'MigrationController::rollback_all');

$router->get('refresh', 'MigrationController::refresh');

$router->get('status', 'MigrationController::status');

These routes provide access to the migration operations.

Migration Routes
Route               Function
/create-migration/
{name}              Create a migration file
/migrate
                    Execute pending migrations
/rollback           Roll back the latest migration
                    batch
/rollback-all       Roll back all migrations
                    Roll back and re-run
/refresh            migrations
                    Display migration status
/status

Part IV -- Create a Custom CLI Command
Instead of executing migration operations only through browser routes,
create a custom LavaLust CLI command.
Run:
php lava make:command Migration
Open the generated command file inside:
app/command/Migration.php
Paste the following:
<?php

class Migration
{

   public static $command = 'migration';

public static $description = 'Run database migrations';

   public static $arguments = [
       '[action]' => 'Action: run, create-migration, rollback, rollback-all,

refresh, status',
       '[name]' => 'Migration class name for create-migration',

   ];

protected static $route_map = [

    'run'           => 'migrate',

    'create-migration' => 'create-migration',

    'rollback'      => 'rollback',

    'rollback-all' => 'rollback-all',

    'refresh'       => 'refresh',

    'status'        => 'status',

];
   public function handle($action = null, array $flags = [], $name = null)
   {

       $action = $action ?? 'run';

       if (!isset(static::$route_map[$action])) {
           echo danger("Unknown migration action: \"{$action}\"");
           echo "Available actions: "
               . implode(', ', array_keys(static::$route_map))
               . PHP_EOL;
           exit(1);

       }

       if ($action === 'create-migration') {

           if (!$name) {
               echo danger("Migration name is required.");
               echo "Example: php lava migration create-migration

create_users_table"
                   . PHP_EOL;

               exit(1);
           }

           $route = 'create-migration/' . $name;

       } else {

           $route = static::$route_map[$action];
       }

       $index = PUBLIC_DIR . 'index.php';

       if (!file_exists($index)) {
           echo danger("index.php not found at: {$index}");
           exit(1);

       }

       $command = sprintf(
           'php %s %s',
           escapeshellarg($index),
           escapeshellarg($route)

       );

       passthru($command);
   }
}

Part V -- Execute the Migration
Run the migration command:
php lava migration run
The command should execute the pending migration files.
The migration system will create the required database tables.
For the API authentication system, verify that the following tables are
available:
users
refresh_tokens
The users table stores user account information, while refresh_tokens stores
refresh-token data used by the API authentication system.

Part VI -- Verify the Database
Open your database management tool, such as:

     MySQL Workbench
     phpMyAdmin
     DBeaver
     Navicat
Select your LavaLust database and verify that the migration-generated
tables exist.
Expected tables:
migrations
users
refresh_tokens
The migrations table is used by LavaLust to track which migrations have
already been executed.

Part VII -- Test Other Migration Commands
Test the following commands:
Check Migration Status
php lava migration status
Create a Migration
php lava migration create-migration create_products_table
Run Pending Migrations
php lava migration run
Roll Back the Latest Migration
php lava migration rollback
Roll Back All Migrations
php lava migration rollback-all
Refresh the Database
php lava migration refresh
Important: rollback-all and refresh can remove and recreate database
structures. Use them only in your development database.
